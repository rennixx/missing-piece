# Missing Piece Complete

The official remediation companion for **Missing Piece**.

While `missing-piece` audits in read-only mode to preserve evaluation trust, `missing-piece-complete` acts upon human-approved audit findings to safely implement the missing behavior.

## Non-Negotiable Remediation Invariants

Every remediation generated by this skill must satisfy:

1. **Target Specificity**: Address one verified omission finding at a time (e.g. `MP-SE-001`). Never introduce unrelated refactoring.
2. **Convention Conformance**: Mirror local project idioms for error handling, dependency injection, naming, and data access.
3. **Atomicity & Boundaries**: Ensure new counterparts execute inside appropriate database transaction or unit-of-work boundaries.
4. **Idempotency & Reversibility**: Counterparts (e.g. cleanup routines, refunds, unreserves) must be safe to retry or execute idempotently.
5. **No Regressions**: Existing positive paths must retain their exact contract and response semantics.
6. **Verifiable Test**: Every completed counterpart must be accompanied by an automated test verifying the previously absent behavior now executes.

## Remediation Procedure

### 1. Ingest Finding & Establish Context
Read the finding details:
- **Observed fact**: What capability triggered the expectation?
- **Gap**: What exact counterpart, handler, or guard is absent?
- **Evidence anchors**: What files and functions define the primary flow?

### 2. Reconstruct Local Neighborhood
Inspect neighboring files and functions to determine:
- How exceptions are handled (custom error classes, HTTP responses, logger calls).
- How state is mutated (ORM models, direct SQL queries, domain events, message publishers).
- How authorization and middleware guards are applied (decorators, function wrappers, router pipelines).
- How transactions are managed (`db.transaction()`, `@transactional`, atomic blocks).

### 3. Design the Counterpart
Synthesize the minimal, idiomatic implementation:
- If a **deletion cleanup** is missing (`MP-LC` / `MP-OC`): Add explicit cascading deletion or enqueue an asynchronous storage purge job.
- If a **timeout/expiration transition** is missing (`MP-ST`): Add a scheduled sweep or explicit timeout guard in state validation.
- If an **inverse counterpart** is missing (`MP-SY`): Implement the symmetric function (e.g. `revoke_role` for `grant_role`).
- If a **mutation guard** is missing (`MP-MG` / `MP-AU`): Apply established auth/permission decorators or middleware checks.
- If a **secondary side effect** is missing (`MP-SE`): Wire the required secondary action (e.g. inventory release, notification) within the transaction or outbox event.
- If a **failure/retry guard** is missing (`MP-FR` / `MP-AS`): Introduce idempotency keys, retry limits, or dead-letter queue routing.

### 4. Apply Changes
Write clean, well-documented code with minimal diff footprints. Preserve all existing docstrings and comments.

### 5. Provide Falsifiable Verification
Generate or run a test verifying:
1. The new counterpart executes successfully on the intended trigger.
2. Edge cases (e.g. already cleaned up, non-existent entity, concurrency) do not crash the primary flow.

```markdown

#### Verification Test
[Command or code snippet verifying the newly implemented counterpart]
```
